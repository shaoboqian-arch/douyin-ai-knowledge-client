# 抖音收藏整理 V{VERSION}

把本机抖音收藏整理成知识库与一批可带走的交付文件。安装包与便携版二选一即可，
全程本机完成，不上传任何内容。

## 安装

| 文件 | 用法 |
|---|---|
| `{SETUP_EXE}` | 双击 → 选安装位置 → 安装；创建桌面/开始菜单快捷方式与卸载项，默认装到 `%LOCALAPPDATA%\抖音收藏整理`，不需要管理员权限 |
| `{PORTABLE_ZIP}` | 解压后双击 `抖音收藏整理.exe`，不写注册表 |

## 首次运行

主按钮是「初始化本机环境」，点开后三步：

1. **项目目录**：选含 `extract_favorites.py` 的抖音采集项目（点「自动发现」可自动找），会同时带出 `.venv` 解释器
2. **抖音账号**：点「校验账号」→ 用项目里的 Cookie 向抖音确认身份 → 点「采用」记录这个账号（以后采集到别的账号会自动中止）
3. **知识库**：默认从项目的 `gen_obsidian.py` 读取，也可手动选；没装 Obsidian 时关掉「同时重建 Obsidian 知识库」即可

三项就绪后，标题右侧出现薄荷主色的「⚠️ 全仓同步」。

## 两个动作

| 动作 | 位置 | 做什么 |
|---|---|---|
| ⚠️ 全仓同步 | 标题右侧、设置左边（薄荷主色） | 必做的一次全收藏扫描：全量采集 → 账号校验 → 增量对比 → 重建 Excel/CSV 与 Obsidian 知识库 → 导出所选范围；每条收藏约 1 秒 |
| 仅导出 | 作品发布日期右侧、浏览下方 | 只读项目里已有的 `work/rows_merged.json` 写批次，不采集、不联网；秒级 |

**先跑一次「⚠️ 全仓同步」**，项目里才有整理结果，「仅导出」才可用。
作品发布日期只决定导出哪些笔记，不影响采集范围；留空表示全部，日期下方实时显示「范围内 N 条」。

## 批次里有什么

每轮新建带时间戳的目录，绝不覆盖已有文件。

```
export-<范围>-<时间戳>/
├─ 01_AI笔记/<AI类别>/<子类别>/*.md
├─ 02_其他收藏/<子类别>/*.md
├─ 03_待判定/*.md
├─ _导出报告.md      计数 / 子类别分布 / 待加工 / 全量明细 / 入库结果
└─ _整理状态.json    程序内部状态（隐藏，用于续跑）
```

《导出报告》是唯一一份给人看的文档。待加工条目写在它的「待加工」一节；主界面进度表右侧的
「补加工」可以复制清单、打开 `work` 目录，补齐后点「仅导出」刷新批次。

## 停止、续跑与门禁

- 采集中主按钮变「停止」；停止后已采集的原始数据保留，但不生成交付
- 采集成功而重建/导出失败时，点「续跑」只重跑重建与导出，不重新采集，结果写成新批次
- 账号 `sec_uid` 与设置不一致，或采集条数低于设置下限，立即中止且不重建交付物

## MCP 接入

把这一键合并进 `~/.workbuddy/mcp.json` 已有的 `mcpServers`（**不要整份覆盖**），
把 `command` 换成本机 exe 的绝对路径：

```json
{
  "mcpServers": {
    "douyin-fav-sync": {
      "type": "stdio",
      "command": "<安装目录>\\抖音收藏整理.exe",
      "args": ["--mcp"],
      "description": "抖音收藏采集与知识库整理"
    }
  }
}
```

保存后到连接器管理 → 自定义连接器 → 对本服务点「信任」才会生效。
验证：新建对话调用 `dy_status`，返回 `ready: true` 即接通。

工具：`dy_status` / `dy_preflight` / `dy_export` / `dy_sync` / `dy_retry` / `dy_report`。
`dy_sync` 会真实采集（每条收藏约 1 秒），`dy_export` 只用已有数据写交付（秒级）。

## 前置条件

- 本机有一个可运行的抖音采集项目（含 `.venv` 与已登录 Cookie）
- 该项目已产出 `work/rows_merged.json`；要重建知识库还需装了 Obsidian，并有含 `00_入口.md` 的库目录

## 边界

- 只读本机项目数据；不访问其它服务、不上传
- 账号或条数不符时一定中止，不重建交付物
- 不做 AI 判定 / 转写 / 介绍 / 概念，只统计缺口
- Cookie 留在原项目，客户端设置里没有它
