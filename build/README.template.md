# 抖音收藏整理 V{VERSION}

把本机抖音收藏整理成知识库与一批可带走的交付文件。安装包与便携版二选一即可，
全程本机完成，不上传任何内容。

## 安装

| 文件 | 用法 |
|---|---|
| `{SETUP_EXE}` | 双击 → 选安装位置 → 安装；创建桌面/开始菜单快捷方式与卸载项，默认装到 `%LOCALAPPDATA%\抖音收藏整理`，不需要管理员权限 |
| `{PORTABLE_ZIP}` | 解压后双击 `抖音收藏整理.exe`，不写注册表 |

## 首次运行

主按钮是「初始化本机环境」，点开后三步：

1. **项目目录**：选含 `extract_favorites.py` 的抖音采集项目（点「自动发现」可自动找），会同时带出 `.venv` 解释器
2. **抖音账号**：点「校验账号」→ 程序用项目里的 Cookie 向抖音确认身份 → 点「采用」记录这个账号（以后采集到别的账号会自动中止）
3. **知识库**：默认从项目的 `gen_obsidian.py` 读取，也可手动选；需要目录里有 `00_入口.md`

三项就绪后按钮变成「开始整理」。

## 使用

1. 选交付目录
2. 填发布时间范围（**留空表示全部**，起止都含当天）
3. 点「开始整理」，阶段依次是：校验 → 采集 → 对比 → 重建 → 导出 → 完成
4. 完成后点「打开」进入批次目录

每轮新建带时间戳的批次目录，绝不覆盖已有文件。批次里的 `_导出说明.txt` 写清了目录含义与计数；
`_待加工.csv` 列出还需要外部 AI 加工的条目（缺判定 / 转写 / 介绍 / 概念）。

### 停止与续跑

- 采集约 25 分钟，期间主按钮变「停止」；停止后已采集的原始数据保留，但不生成交付
- 采集成功而重建/导出失败时，点「续跑」只重跑重建与导出，不重新采集

## MCP 接入

把这一键合并进 `~/.workbuddy/mcp.json` 已有的 `mcpServers`（**不要整份覆盖**），
把 `command` 换成本机 exe 的绝对路径：

```json
{
  "mcpServers": {
    "douyin-fav-sync": {
      "type": "stdio",
      "command": "<安装目录>\\抖音收藏整理.exe",
      "args": ["--mcp"],
      "description": "抖音收藏采集与知识库整理"
    }
  }
}
```

保存后到连接器管理 → 右上角自定义连接器 → 对本服务点「信任」才会生效。
验证：新建对话调用 `dy_status`，返回 `ready: true` 即接通。

工具：`dy_status` / `dy_preflight` / `dy_export` / `dy_sync` / `dy_retry`。
`dy_sync` 会真实采集（约 25 分钟），`dy_export` 只用已有数据写交付（秒级）。

## 前置条件

- 本机有一个可运行的抖音采集项目（含 `.venv` 与已登录 Cookie）
- 该项目已产出 `work/rows_merged.json` 与 Obsidian 知识库（含 `00_入口.md`）

## 边界

- 只读本机项目数据；不访问其它服务、不上传
- 账号或条数不符时一定中止，不重建交付物
- 不做 AI 判定/转写/介绍/概念，只统计缺口
- Cookie 留在原项目，客户端设置里没有它
