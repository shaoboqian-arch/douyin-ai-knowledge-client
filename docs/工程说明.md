# 抖音收藏整理 · V0.2.0

把「抖音收藏 AI 知识库」原来的一串手工命令，封装成一个可安装的 Windows 客户端 + 一个 MCP 接口。
**交付物在 `dist/`**。功能规格对齐 `wx-export-app` V0.5.0，界面拉平为海岛浅色：短路径主界面、批次目录、逐条进度、
分类计数、缺口清单、只读「刷新数据」、续跑、初始化、设置页、MCP、安装包 + 便携版、15 步复检门禁。

## 2. 界面

**V0.1.3 起批次只留一份人看的文档**：原 `_导出清单.csv` / `_导出报告.csv` / `_待加工.csv` /
`_导出说明.txt` 合并为 `_导出报告.md`，`_整理状态.json` 改为隐藏的内部状态。

**V0.2.0 按职责分层布局**：顶栏（数据源区）放「⚠️ 全仓同步」与只读「刷新数据」；「导出设置」卡片（导出目录、作品发布日期 + 「导出文件夹」）专门处理按日期整理出新批次文件夹；底部状态行显示结果与「入库报告 / 续跑 / 打开文件夹」。日期下方实时显示「范围内 N 条」，避免把「导出范围」误当成「采集范围」。待加工列表右侧有「补加工」，可复制待办清单或 AI 补齐指令。

**进度与待加工面板**（点同步 / 导出 / 刷新数据后常驻展示，取消「收起」按钮；待加工为 0 时隐藏空表收成紧凑提示）：

- 阶段：`校验 → 采集 → 对比 → 重建 → 导出 → 完成`，当前阶段高亮
- 分类计数：`视频 / 图集 / 其中 · AI 笔记` 各自 `总数 · 已写出 · 待加工`
- **待加工清单**（可滚动）：每条写清缺哪一步（AI 判定 / 转写 / 百字介绍 / 概念标引）
- 采集时按页显示「第 N 页 · 累计 X 条」；导出时按条推进进度条
- 完成后以引擎返回的权威统计收口

其他按需出现的元素：进度条、完成后的「打开文件夹」、环境异常时的 `ⓘ`（悬停/点击看详情）；
窗口居中、进程级 DPI 感知、系统 CJK 字体回退（V0.1.4 起所有控件默认字体共用
`fonts()` 探测到的 `FONT_FAMILY`）、唯一主按钮加粗、应用图标（`build/make_icon.py` 生成，
PE 已验证含 RT_ICON）、回车触发主操作、Esc 关闭、记住上次交付目录与日期范围。

**与 wx V0.4.3 的差异（有意为之）**：

| 项 | wx V0.4.3 | 本项目 | 理由 |
|---|---|---|---|
| 主操作 | 「导出」 | 「⚠️ 全仓同步」+「刷新数据」+「导出文件夹」 | 顶栏管数据源同步与只读刷新，导出卡片按日期写出新批次文件夹，各司其职不混淆 |
| 运行中 | 禁止关窗 | 主按钮变「停止」，确认后中止 | 全收藏扫描是必做项，单轮可能几十分钟，不允许中止不现实 |
| 日期 | 必填 | 留空 = 全部 | 知识库是全量同步，默认按时间段会漏 |
| 关闭 | 直接拒绝 | 二次确认后中止并退出 | 同上 |

**设置页面**（主界面「设置」进入）按用途分三块：**采集来源**（项目目录、抖音账号，
每项配一行说明）、**知识库**（开关、库目录、库现状）、**高级**（MCP 接入默认折叠）。
底部固定「保存 / 关闭」，环境状态一行。

**初始化页面**（首次运行主按钮）：项目目录（自动发现）→ 校验账号并采用 → 知识库目录。
三项就绪后，标题右侧才出现「⚠️ 全仓同步」；项目里还没有 `rows_merged.json` 时
「导出文件夹」禁用，首页常驻「先做一次全仓同步」提示。

## 3. 两级分类（V0.1.0 起）

一级（AI类别）是客户端化之前那 7 个类别，**不改、不重算**；二级是新增子类别：

| 层 | 取值 |
|---|---|
| AI 相关 | 开源项目与免费资源 · Skill 类 · Skill 与 Agent 用法 · 提示词与模板 · 教程与实操 · 工具测评与选型 · 行业资讯与观点 · 原理与科普 · 变现与商业 · 其他AI相关 |
| 非 AI | 知识科普 · 影视与动漫 · 娱乐与游戏 · 音乐与才艺 · 美食 · 旅行与城市 · 健身运动 · 数码与工具 · 手工与创作 · 职场与财经 · 情感与成长 · 健康与养生 · 生活记录 · 其他 |

落地位置：`01_AI笔记/<AI类别>/<子类别>/`、`02_其他收藏/<子类别>/`；`03_待判定/` 不套子类别。
笔记 frontmatter 写「子类别」与 V0.1.4 补回的「子类别依据」（规则命中词，可逐条复核）；
《导出报告》带完整层级的子类别分布与同层级明细。

**判定口径**（`src/subcat.py`）：确定性有序规则，匹配标题 + 话题 + 归纳 + 介绍 + 转写节选。

AI 顺序：Skill/Agent 且出现「怎么用/如何/搭建/编排…」→ Skill 与 Agent 用法；否则有 Skill/Agent →
Skill 类；否则开源/免费/GitHub → 开源项目与免费资源；否则提示词/指令/模板 → 提示词与模板；
之后教程 → 测评 → 资讯 → 原理 → 变现 → 其他AI相关。
非 AI 顺序：知识科普 → 影视与动漫 → 娱乐与游戏 → 音乐与才艺 → 美食 → 旅行与城市 →
健身运动 → 数码与工具 → 手工与创作 → 职场与财经 → 情感与成长 → 健康与养生 → 生活记录 → 其他。

三条纪律：

- **不调用模型**：规则可复跑、结果可复现，命中词写进清单，能逐条核对。
- **上游优先**：行里已有「子类别」就直接用，依据写「上游标注」，不覆盖上游判断。
- **不硬凑**：没有命中就落到「其他 / 其他AI相关」，不为了好看瞎归类。

实测覆盖率（本机真实库一轮，条数不写进公开文档，具体数字见 `验证输出/`）：

| 范围 | 命中具体子类别 | 落到兜底 |
|---|---:|---:|
| AI 相关 | 96% | 4%（其他AI相关） |
| 非 AI | 61% | 39%（其他） |
| 近一个月的一批 | 92% | 8% |

非 AI 的长尾集中在：只有作者名/一句话的图集、带货口播、追星向、生存类游戏解说 ——
标题与话题里没有可判定的类别信号。这类不是规则写漏，而是**输入信息不足**：
上游 AI 加工阶段若写入「子类别」，客户端会直接采用（依据列写「上游标注」）。

## 4. Obsidian 知识库对接与入库报告

**前提**：本机装了 Obsidian，并已在设置里指定知识库目录。没装也能用 —— 只是关掉知识库重建，
Excel 与批次交付照常。

### 4.1 对接方式

- **检测**：注册表 `HKCU\Software\Classes\obsidian\shell\open\command` → 常见安装位置；
  库清单读 `%APPDATA%\obsidian\obsidian.json`（含每个库的路径与 `open` 标记）。
- **开关**：设置页「整理后重建 Obsidian 知识库」。未检测到 Obsidian 时开关禁用，
  初始化页会提示「可先只用表格与批次交付」。
- **不重写基线**：仍然调项目的 `gen_obsidian.py` / `audit_obsidian.py`，参数与 `cwd` 和手工运行一致。
- **现状行**：设置页显示「已检测到 Obsidian · 库 N 个 · 现状 X 收藏 / AI X / X 概念 / X 共现」，
  数字由 `kbreport.snapshot_stats()` 从 `rows_merged`、知识库文件、`concepts_merged` 实算，
  不写死任何条数。
- **打开**：`obsidian://open?path=<库绝对路径>`；失败时退回资源管理器打开目录。

### 4.2 入库报告（8 行，全部从文件反推）

| 环节 | 口径 |
|---|---|
| 身份校验 | 采集日志的账号 + `sec_uid` 是否与设置一致 |
| 新增收藏 | `raw` 与上一版快照的作品 ID 差集；AI/非 AI/待判定拆分与类别分布 |
| 取消收藏 | 同上差集的反方向；档案是否同步清洗（`make_tables` 重建即视为清洗） |
| 视频转写 | 新 AI 视频中有 `work/transcripts/<id>.txt` 的条数；客户端不转写 |
| 百字介绍 | 新 AI 条目中 `内容介绍` 非空的条数 |
| 概念标引 | 新 AI 条目中已有概念的条数 + 本轮新增概念 |
| 重建交付物 | Excel（总/AI/TOP20）+ Obsidian（笔记/概念/共现）实算 |
| audit 体检 | `audit_obsidian.py` 退出码与末行结论 |

共现关系数由 `concepts_merged` 的「同一条目内概念两两组合」去重复算，与知识图谱里的共现数
一致（`tests/verify_real.py` 有独立复算断言，不依赖硬编码数字）。

报告不再单独成文件：同步结束后作为「入库结果」一节追加到批次里的《导出报告.md》；
机器可读副本写在 `_入库报告.json`（设为隐藏，供界面与 CLI/MCP 读取）。
界面状态行「入库报告」按同一份 JSON 渲染，支持复制、另存为 md、打开知识库。
CLI/MCP 用 `--cli --report --batch` 与 `dy_report` 读取。

## 6. 与基线的边界

- **不改抖音项目任何脚本**：`extract_favorites.py` / `weekly_prepare.py` / `make_tables.py` /
  `gen_obsidian.py` / `audit_obsidian.py` 原样调用，`cwd` 就是项目根，参数与手工运行一致。
- **不搬运 Cookie**：客户端只读 `Volume/settings.json` 判断「有没有、多长」；
  `src/_data/settings.json` 的字段里没有 Cookie。
- **不重算一级分类**：AI 判定、7 个大类、转写、百字介绍、概念标引全部沿用项目产物；
  子类别只加在导出这一层，不写回 `rows_merged.json`。
- **知识库目录以脚本为准**：`kb_dir` 默认从 `gen_obsidian.py` / `audit_obsidian.py` 的字面量里读，
  改库只改脚本，客户端跟着走。

## 7. 构建与一键复检

```bash
python build/build.py
python tests/run_all.py 轮次名
```

- **版本号唯一真源是 `src/common.py` 的 `VERSION`**（当前 `0.1.8`），构建、窗口标题、
  MCP `serverInfo`、`--version`、交付文件名都跟它走。
- `pyinstaller==6.22.3` 用 `pip --target build/vendor` 装在隔离目录，不污染系统 Python。
- PyInstaller 单文件 `--console`（MCP 需要 stdout），GUI 启动时只在「控制台由自己独占」时隐藏；
  从终端启动不会把用户的终端窗口一起藏掉（`GetConsoleProcessList` 判定）。
- 图标通过 `--icon` 写入 PE 资源。

复检 15 步：矩阵、子类别、知识库与报告、新用户路径、清单复核、界面、界面改动、MCP 全链路、
MCP 兼容、设置页、命令行（含冻结态截图）、公开面、真实数据只读回归、审计一致性、F 清单闭环。
汇总写入 `验证输出/全量复检-<轮次>.json`。

## 8. 发版流程（上传前必须自检）

谁来打标签、传 Release 都走这一套。自检未通过，不上传。

1. **升版**：只改 `src/common.py` 的 `VERSION`。构建、测试和交付文件名都跟它走。
2. **构建**：`python build/build.py`，末尾的 PE 头 / `--version` / 文件大小自检必须通过。
3. **全量自检（门禁）**：`python tests/run_all.py Vx.y.z`（轮次名用本版号）必须 15/15 PASS。
   任何一步失败，先修再复跑，不要带着失败结果上传。
4. **复检产物只留本机**：`验证输出/`、真实整理批次、密钥、Cookie 都不进 Git、不挂 Release、不送云端代理。
5. **公开材料再扫一遍**：必须先跑 `python tests/verify_public_safe.py`，未通过不准上传。
   本机敏感词名单是 `tests/public_safe.local.txt`（不进 Git；可先复制 `tests/public_safe.local.example.txt`），
   缺文件或名单为空时检查不通过。脚本命中时只报文件与行号，不打印敏感词原文；
   还会检查提交作者是否都是 GitHub noreply、标签是否都落在当前可达历史、名单本身未被跟踪，
   并按 `git ls-files` 扫描已跟踪文本（含已跟踪的 dist/build 说明）。V0.1.4 起还会解压检查
   安装包 exe / 便携版 zip 的内容是否夹带本机敏感词，并核对版本号、按钮名与交付文件名
   在 README / 工程说明 / 安装包说明里是否一致。图片由脚本跳过。
   同时再人工确认 README、本说明、源码注释、即将写的 Release 说明，以及 `docs/images/` 等截图里，
   不能出现个人账号目录、本机绝对路径、真实批次名，或其他能对上本人的细节。
6. **跟踪文件确认干净**：待提交内容不含安装包、密钥、验证输出、真实批次、`src/_data/`、`build/vendor/`。
   安装包只走 Releases。
7. **上传最新一版**：公开仓只保留当前最新介绍与 Release，不提供历史版本下载。
   附件用 ASCII 文件名（`douyin-fav-sync-Setup-Vx.y.z.exe` / `douyin-fav-sync-Vx.y.z-portable.zip`），
   中文名放在附件标签上。
8. **上传后核对**：本机 `dist` 与 Release 附件的 sha256 一致；窗口标题 / 安装向导 /
   MCP `serverInfo` / `--version` 都是本版号；源码包和介绍页没有第 5 步要清掉的个人信息。

## 9. MCP 兼容性

| 项 | 结论 |
|---|---|
| 配置文件 | `~/.workbuddy/mcp.json`（**不带点**），顶层 `mcpServers` |
| stdio 条目 | `type: "stdio"` + `command` + `args` + `description` |
| 启用 | 写入**不会自动生效**；连接器管理 → 自定义连接器 → 点「信任」 |
| 验证 | 新对话调用 `dy_status`，返回 `ready: true` 即接通 |
| 超时 | 官方建议单次 ≤30 秒；`dy_sync` 用时随收藏数等比（每条约 1 秒），建议用 `dy_preflight` 先看规模 |

复检本身踩过一个坑（已修）：GUI 冻结态继承父进程 stdout 时，PyInstaller 派生的子进程若未随父进程
一起结束，管道不关闭会让 `run_all` 一直等 EOF（表现为「命令行」永远不结束）。
修法是给 GUI 的 stdio 接 `DEVNULL`，并用 `taskkill /T /F` 连子进程一起收掉。

## 11. 边界与待决定项

- **项目锁（与每周增量编排互斥）**：`sync` / `retry` 全程持 `ProjectLock`
  （`Local\douyin-fav-sync.<client|weekly>.<项目路径 sha256 前 12 位>`）——入口 `acquire()`、
  `finally` `release()`，中途抛异常也不会漏放；同进程重复加锁立即报错，
  `CreateMutexW` 失败按 fail-closed 处理（宁可不跑，也不并发写）。开跑前先查对方的
  `weekly` 互斥体，活跃即中止让路；互斥体随进程退出自动释放，无残留文件。
  每周任务侧的持锁 / 查锁命令与项目哈希（4436605fac75）见其《全流程》手册第 0 步。

- **AI 判定/转写/介绍/概念不在客户端做**：这些需要外部 AI 处理，客户端只统计缺口，
  《导出报告》的待加工一节逐条写缺哪一步。这是产品边界，不是实现缺陷。
- **子类别是规则推断，不是语义理解**：长尾（IP 名称、书籍观点、明星向）会落到「其他」；
  需要更准时，应在上游（AI 加工阶段）写入「子类别」，客户端会自动优先采用。
- **采集用时随收藏数等比**（每条收藏约 1 秒；本机 ~1.8k 条整轮约 25 分钟，历史声明）：
  受网络与账号限流影响；停止后已采集原始数据保留，但不生成交付。
- **账号硬门禁不可关闭**：账号不符或无法核对即中止，不重建交付物。宁可这一轮没有交付，也不让错账号的数据进知识库。
- **条数下限门禁已移除**（2026-11-18 用户裁决）：分发场景无法预知用户的收藏量级，
  固定下限（旧默认 1000）会误伤小库用户。部分采集的风险改由《导出报告》的
  新增 / 取消收藏差集揭示——差值异常大时人工判断本轮数据是否可用。
- **真实 WorkBuddy 客户端未端到端接入验证**：MCP 验证用的是自建严格客户端
  （双帧 + 完整握手），不是 WorkBuddy 桌面端的 MCP 客户端；设置页「测试连接」可随时自检，
  连接器管理页的「信任」需要人工点一次。
- **卸载未在真实环境执行**（会写注册表/删快捷方式），只做代码级检查。
- 单文件 exe 首次启动需要数秒自解压；改 `--onedir` 可降到约 1 秒，但交付形态会变，
  属交付形态决策，未擅自改。
